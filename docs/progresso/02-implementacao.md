- **Implementado no repositório `keepalive`** (`github.com/rasecdev/keepalive`, fora deste repositório): env var `MIN_MEMORY_MB` aloca um `Buffer` residente no boot. **Achado durante o teste:** o primeiro `fill(0)` do `Buffer.alloc` não força RSS real — páginas anônimas já nascem zeradas pelo kernel, então escrever zero de novo não comete páginas físicas; corrigido preenchendo com valor não-zero logo após alocar (commits `7f84c96` e `1318983`, testado local antes de ir pra produção). - **Decisão explícita do usuário antes de escrever código (2026-09-09): `categoria` continua `TEXT` livre, sem criar tabela `categorias` formal nem FK.** Pesquisa feita antes da decisão: Firefly III e Actual Budget (referências open source) também não têm taxonomia fixa hardcoded, categoria é sempre definida pelo usuário; Open Finance Brasil/Bacen **não padroniza categoria de gasto** — a especificação real (`EnumTransactionTypes` da API de Contas) só padroniza mecanismo de transação (PIX, TED, boleto, saque, cartão...), nunca natureza de gasto; o Pluggy tem categorização própria (IA proprietária, campo `category`), mas não é padrão do Bacen nem do mercado; a taxonomia PFC do Plaid (18 categorias primárias, 104 detalhadas) é usada pela indústria de fintech americana, mas não pelo Pluggy — adotá-la agora não traria interoperabilidade real com o dado que a Fase 8 vai consumir, e formalizar `categorias` agora seria escopo maior que o pedido, chutando uma lista sem dado real de uso.
